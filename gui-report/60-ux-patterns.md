# UX patterns for an agent GUI, and a wireframe for TMT

Research date 2026-10-01 (20:58 NZDT). Evidence is from product docs fetched today plus search results; anything from memory or a single weak source is marked UNVERIFIED. I could not get usable docs for Goose permissions, gptme UI, Windsurf internals or Codex-app approvals, so those rows lean on search snippets or are marked.

## 1. What the leading apps do

| Concern | Pattern and evidence |
|---|---|
| **Approval prompt, scope of "always"** | **Claude Code**: tiered table, read-only needs no approval; bash "Yes, and don't ask again" is remembered *permanently per repository and command*; file edits "until session end"; web fetch per repository and domain ([permissions](https://code.claude.com/docs/en/permissions)). Modes: Manual (default), plan, acceptEdits, bypass, plus an "auto mode" where a classifier reviews actions instead of you. Anthropic's own engineering post reports users approve about 93% of prompts, which is why auto mode exists ([auto-mode post](https://www.anthropic.com/engineering/claude-code-auto-mode), figure from search snippet). **Zed**: allow/deny once, tool-level permission, or **create a pattern-based rule directly from the approval dialog**; rule precedence built-in rules, `always_deny`, `always_confirm`, `always_allow`, tool default, global default; patterns are regexes such as `^cargo\s+(build|test)` ([tool permissions](https://zed.dev/docs/ai/tool-permissions)). **VS Code Copilot agent**: inline confirmation with scopes session / workspace / always; terminal allowlist patterns with warnings before auto-approving environment-altering commands ([agent tools](https://code.visualstudio.com/docs/copilot/agents/agent-tools)). |
| **Inline vs modal** | The trend is **inline in the thread**: VS Code documents an "inline confirmation dialog" for tool calls (same page); Zed shows approvals inside the agent thread (UNVERIFIED wording, docs fetched describe a "dialog" with pattern creation); Claude Code's prompt is part of the conversation flow in the terminal and VS Code panel. I found no evidence that a blocking OS-modal is the pattern in these apps. |
| **Diffs and per-hunk accept/reject** | **Zed**: after edits, an accordion lists affected files with line counts; "Review Changes" opens a multi-buffer view where **individual hunks can be accepted or rejected** ([agent panel](https://zed.dev/docs/ai/agent-panel)). **Claude Code VS Code**: inline diffs, plan review before accepting, auto-accept edits option ([VS Code docs](https://code.claude.com/docs/en/vs-code)). **Copilot**: Keep / Undo pending edits, with a long-running bug class where Keep/Undo overwrote valid work ([discussion 183864](https://github.com/orgs/community/discussions/183864), [issue 263856](https://github.com/microsoft/vscode/issues/263856) asks for auto-accept). **Windsurf Cascade**: stages edits as a reviewable diff; a reported regression removed per-change accept/reject ([codeium issue 131](https://github.com/Exafunction/codeium/issues/131)). |
| **Plans / todo lists** | **Windsurf Cascade** breaks a request into a todo list and works through it ([docs](https://docs.windsurf.com/windsurf/cascade/cascade)). **Claude Code**: plan mode lets you review and edit the plan before accepting it ([VS Code docs](https://code.claude.com/docs/en/vs-code)). **Cursor** lists "clarification: ask questions while continuing work" as a core tool and has a `/goal` command ([overview](https://cursor.com/docs/agent/overview)). |
| **Background / parallel agents** | **Zed**: parallel threads with independent context, `ctrl-tab` switching, archive, a **sidebar of threads grouped by project** ([agent panel](https://zed.dev/docs/ai/agent-panel)). **Claude Code**: a subagent panel in the footer, `/tasks` for background shell tasks, long commands auto-move to background ([interactive mode](https://code.claude.com/docs/en/interactive-mode), snippets). **ChatGPT/Codex desktop**: "keep every chat in view", projects, parallel workstreams ([app overview](https://learn.chatgpt.com/docs/app); Codex-specific worktree/review UI UNVERIFIED, the fetched page was marketing-level). **Cursor**: multiple agents coordinated by Projects ([overview](https://cursor.com/docs/agent/overview)). |
| **Token / cost meter** | **Zed** shows token consumption in the panel and auto-compacts near the threshold ([agent panel](https://zed.dev/docs/ai/agent-panel)). Others: status-line/footer meters (UNVERIFIED for specific apps). |
| **Cancel / stop** | **Claude Code**: Esc interrupts "mid-turn so you can redirect"; Claude keeps the work done so far; queued messages are sent next ([interactive mode](https://code.claude.com/docs/en/interactive-mode)). Esc-Esc on an empty prompt opens rewind. |
| **Queued follow-ups** | **Cursor**: Enter queues until the task finishes; Cmd+Enter sends immediately to *steer*; `/side` for tangents ([overview](https://cursor.com/docs/agent/overview)). **Zed**: messages queue by default, a "Steer" toggle interrupts between tool calls ([agent panel](https://zed.dev/docs/ai/agent-panel)). **Windsurf**: type while Cascade works and press Enter to queue ([docs summary](https://docs.windsurf.com/windsurf/cascade/cascade)). **Claude Code**: queued entries are listed in the conversation until sent; some queued messages join the running turn and are then **not checkpointed** ([checkpointing](https://code.claude.com/docs/en/checkpointing)). Pattern: *queue* versus *steer* are two distinct, explicit actions. |
| **Checkpoints / undo** | **Claude Code**: automatic checkpoint before every prompt that starts a turn, last 100 kept, `/rewind` or Esc-Esc; options: restore code and conversation / conversation only / code only / summarize from or up to here; **bash-made changes, subagent edits, external changes and symlinks are not restored**; "not a replacement for version control" ([checkpointing](https://code.claude.com/docs/en/checkpointing)). **Cursor**: checkpoints before significant changes, stored locally and separate from Git ([overview](https://cursor.com/docs/agent/overview)). **Zed**: a restore button above each message ([agent panel](https://zed.dev/docs/ai/agent-panel)). **Copilot**: snapshot before each request, restores files and chat history, does not reverse terminal commands or external effects ([checkpoints](https://code.visualstudio.com/docs/copilot/chat/chat-checkpoints)). **Windsurf**: named checkpoints, revert arrow on the prompt, "reverts are currently irreversible" (docs summary). |
| **Goose, gptme** | Goose desktop has permission modes (autonomous / manual / smart / chat-only): UNVERIFIED, my docs fetch was empty. gptme's web UI and desktop app exist (see 20-web-shells.md section 17) but I did not find UX documentation; no claims made. |

## 2. TMT feature -> best pattern seen

| TMT feature | Best pattern seen | App | Why it fits TMT |
|---|---|---|---|
| `approve(question, pattern)` with "always" = remembered pattern | Approval card with **Allow once / Always allow `<pattern>` / Deny**, and the pattern editable and visible; saved rules listed in settings with deny > confirm > allow precedence | Zed (pattern rules created from the dialog), Claude Code (per repository + command), VS Code (session/workspace/always scope) | TMT's remembered *pattern* maps one-to-one onto Zed's pattern rule; show scope in the button text ("Always for this project: `git push *`") so "always" is never ambiguous |
| `ask_user` with up to 5 one-key options | Inline question card with numbered buttons, each bound to its key (1-5), Esc = dismiss (the `""` answer), plus "nobody here" handled by the engine | Cursor "clarification while continuing work"; ACP `elicitation/create` | Keeps TMT's one-keystroke speed in a GUI; dismissal and no-UI stay distinct answers |
| `/plan` held to completion | Persistent plan panel in the sidebar with step status, and plan review before execution | Windsurf todo list, Claude Code plan mode | A plan that blocks completion needs to be visible at all times, with the blocking step highlighted |
| `/undo` checkpoints | Restore control on each turn/message, with a menu of what is restored (code / conversation / both); show what is NOT covered (shell side effects) | Claude Code `/rewind`, Zed per-message restore | TMT's checkpoints are workspace-file snapshots; copy Claude Code's honesty about bash changes and make restore previewable (matches `undo.preview`) |
| `/review` and `/verify` | Review changes view: multi-file list with per-hunk accept/reject and a gate status chip | Zed Review Changes multi-buffer; Copilot Keep/Undo | These are gates, so surface pass/fail as a persistent chip next to the diff, not just a transcript line |
| Up to 10 background agents | Thread sidebar, one row per agent with status, last activity, tokens; click opens its transcript; stop button per row | Zed thread sidebar, Claude Code subagent panel, Codex/ChatGPT multi-chat | TMT already has a live panel with per-agent rows; a sidebar is the GUI equivalent, driven by `agents.changed` |
| Type-ahead queue | Queued messages shown as removable chips above the prompt; **Enter = queue, Ctrl+Enter = steer now** | Cursor, Zed (Steer toggle), Claude Code | Matches TMT's type-ahead; the explicit steer action avoids accidental interrupts |
| Image attach | Paste/drag thumbnail chips in the prompt box; vision-capable-model check | Zed (images via @-mentions, vision models only) | Chips with remove buttons; disable with an explanatory tooltip when the model has no vision |
| Token and elapsed readout | Status bar: model, context used/limit, elapsed, cost; compaction notice | Zed token tracking and auto-compaction | TMT already tracks `usage` and elapsed per turn |
| Cancel | Prominent Stop button + Esc; keep work done so far; show "cancelled, N changes kept" | Claude Code Esc semantics | Maps to `turn.cancel` / `stopReason: cancelled` |

## 3. Proposed wireframe (Windows main window)

Inline approval card in the transcript (not a modal), because every app above that documents tool approval puts it inline or in-thread, and inline keeps the prompt box, scrollback and sidebar usable while the engine waits. Use a modal **only** for destructive workspace-level questions at startup (e.g. adopting a non-git folder), where nothing is running yet.

```
+----------------------------------------------------------------------------------------------+
| TMT   [C:\proj\app v] [ + tab ]   Tabs: [ fix-login ][ docs ]                 [Settings] [_][#][x]|
+------------------------------------------------------------------+---------------------------+
| TRANSCRIPT                                                       | SIDEBAR   [Plan][Agents][Review]|
|                                                                  |---------------------------|
|  You  10:41  Fix the failing login test                          | PLAN  (held to completion)|
|                                                                  |  [x] S1 Reproduce failure |
|  TMT  Looking at tests/test_login.py ...                         |  [>] S2 Fix token expiry  |
|   > read_file  auth.py                         0.4s  [v]         |  [ ] S3 Run verify gate   |
|   > edit auth.py   +6 -2                       [Open diff]       |---------------------------|
|   | @@ -41,7 +41,11 @@ def refresh(token):                      | AGENTS  3 / 10            |
|   | -    if token.exp < now:                                     |  * tests   running  1.2k t|
|   | +    if token.exp <= now + SKEW:                             |  * lint    done            |
|   |        [Accept] [Reject]   (per hunk)                        |  * docs    waiting  [Stop]|
|                                                                  |---------------------------|
|  +--------------------------------------------------------+      | REVIEW  /verify: PASS     |
|  | Run command?                                           |      |  2 files, +9 -3           |
|  | git push origin fix-login                              |      |  [Review changes]         |
|  | [Allow once] [Always: git push *  (this project)] [Deny]|     |  [Undo last turn v]       |
|  +--------------------------------------------------------+      |                           |
|  (engine is paused until you choose; Esc = Deny)                 |                           |
+------------------------------------------------------------------+---------------------------+
| Queued: [ also update the README (x) ] [ run lint after (x) ]        [Steer now]            |
| +----------------------------------------------------------------------------------------+ |
| | Type a task...   [img: shot.png (x)]                             [Attach] [Send] [Stop] | |

| claude-sonnet-5-5 | effort: med | ctx 38k/200k | 12.4k out | 00:42 elapsed | $0.08 | main* |

```
Notes: Enter queues while a turn runs and Ctrl+Enter steers; the question card for `ask_user` uses the same inline slot with numbered buttons (1-5); the transcript shows a "jump to latest" pill instead of force-scrolling when the user has scrolled up.

## 4. Five do / don't rules (from documented complaints)

1. **Do tier approvals and make "always" explicit; don't prompt for everything.** Cursor users report agent mode "constantly asking permission" and approval on every edit, especially with worktrees and parallel agents, which "defeats the purpose" ([Cursor forum](https://forum.cursor.com/t/agent-mode-constantly-asking-permission-for-doing-anything/114313), [worktree thread](https://forum.cursor.com/t/cursor-agent-in-worktree-always-asks-for-permission-to-create-cursor-workspace-pr-body-txt/151894)); a figure of 93% of prompts approved is quoted in analyses of Claude Code ([auto-mode post](https://www.anthropic.com/engineering/claude-code-auto-mode)), and write-ups argue that blanket prompts train users to click through ([WorkOS](https://workos.com/blog/approval-fatigue-agent-governance)). So: keep read-only and policy-ALLOW silent (TMT's `agent_policy` already does), show scope in the button label, and let users promote a prompt into a saved pattern.
2. **Do let the reader own the scroll position; don't auto-scroll while the user is reading.** Multiple agent UIs have open bugs where streaming output yanks the viewport ([Claude Code desktop #53382](https://github.com/anthropics/claude-code/issues/53382), [hermes-agent #38272](https://github.com/NousResearch/hermes-agent/issues/38272), Cline fix [PR 14635](https://github.com/cline/cline/pull/14635), [coder PR 29354](https://github.com/coder/coder/pull/29354)). Rule: suspend follow-mode on any upward scroll, resume only at the bottom or via a "jump to latest" button; keep streamed blocks height-stable.
3. **Do make checkpoints trustworthy and honest; don't ship a restore button that sometimes disappears or lies about scope.** Cursor forum reports show "Restore Checkpoint" missing, restoring in surprising ways, or destroying history ([missing button](https://forum.cursor.com/t/restore-checkpoint-missing/167908), [destroys history](https://forum.cursor.com/t/restore-checkpoint-permanently-destroys-change-history/129652)); Windsurf reverts are "irreversible"; Copilot's Keep/Undo has overwritten valid code ([discussion](https://github.com/orgs/community/discussions/183864)). Rule: preview before restore (`undo.preview`), make restore itself undoable or snapshot first, and state what is not covered (Claude Code and Copilot both document that shell/external effects are not rewound).
4. **Do separate queue from steer; don't let a typed follow-up silently interrupt or silently vanish.** Cursor, Zed and Windsurf all expose queue-by-default with an explicit steer/send-now action; Claude Code's docs even call out that mid-turn messages are not checkpointed. Show queued items as visible, removable chips.
5. **Do keep granular, per-hunk control and never remove it; don't force all-or-nothing review.** Windsurf's loss of per-change accept/reject was reported as a regression ([codeium #131](https://github.com/Exafunction/codeium/issues/131)), and Copilot users ask for auto-accept or revert-all buttons ([#263856](https://github.com/microsoft/vscode/issues/263856), [#292741](https://github.com/microsoft/vscode/issues/292741)). Offer per-hunk accept/reject plus an auto-accept option and a "revert all".

Caveat: the complaint evidence is user-reported forum and issue content, not measured prevalence; the star counts and release dates elsewhere in this report folder are unrelated to this file.
