# TMT CLI UI review, 2026-10-25

Method: `python TMT.py` driven through a ConPTY window rendered by pyte (`output/sim/tui_driver.py`), main size 120x36, then 80x24, 60x20 and 160x50. Screenshots are in `C:\Coding\TMT\output\sim\shots\` (abbreviated `shots/` below). One real task was run on Provider = Anthropic, route = Claude subscription, model Claude Haiku 4.5, in a throwaway workspace `output/sim/ws`. The task worked: `notes.txt` was created containing `hello`.

Limits of this review: the screenshot font (Consolas) has no glyphs for the legacy welcome screen symbols, so the empty boxes in `shots/16` are a renderer limit, not a TMT bug (but see F13). Reply Format JSON/TAGS only changes the label. Danger Zone was only looked at. Rows and columns are 0-based, as in the driver dumps.

## Findings in detail

### F01 High: Esc on the main menu quits TMT
- Screen: main menu (shots/02, shots/12). Size 120x36. Repro: Settings or Help, Esc back to the menu, Esc again: the process exits. It happened twice by accident during this review.
- Footer says `Up/Down Navigate    Enter Select` only. Every other screen uses Esc as Back.
- Fix: ignore Esc on the menu, or ask for a confirm (Esc again, or Exit item); add `Esc Exit` or `q Quit` to the footer if it stays.

### F02 High: Start without a key, then Esc, is a dead end into the legacy welcome flow
- Screens: shots/13 (rows 1-12: "TMT needs an API key before it can start. Paste one here." with footer "Esc Back"), then shots/16 and shots/17. Size 120x36.
- Esc on shots/13 (the footer and the line at row 10 both promise "go back to the menu") opens a second, different screen: the boxed "W E L C O M E T O T M T" (rows 9-16) with a prompt `paste key` at row 19. Esc does nothing there, Enter prints "That was empty" and moves the bar 40% to 55% (rows 20-22), and Ctrl-C prints "Setup cancelled" and ends the whole program (shots/17 shows the process dead). A user who just wants the menu has no way back.
- Fix: Esc on the key-gate screen should return to the main menu. Delete the legacy flow or make Esc work in it; stop having two key-entry designs.

### F03 High: no echo while typing or pasting a key
- Screens: shots/08-apikey-abc, shots/11, shots/14-apikey-tooshort-noecho. Size 120x36. Anthropic and OpenRouter both.
- Right after opening the screen, typed `sk-or-v1-fake` (and `abc`, `x`) shows nothing: row 8 stays `Key   paste or type it; only * is echoed` and rows 9-11 stay empty. The text is accepted: Enter said "That is too short for a OpenRouter key" (shots/14) so the input was there but invisible. After an error message is on screen, the same input does echo `*` (shots/15: row 8 shows 114 `*` filling the line to col 119, and `abc`+`d` gave `****`). So first input on a fresh screen is not drawn.
- Also seen once: a very long paste (333 chars) followed by more typing left the field reading "Nothing was typed" on Enter (shots/09); not reproduced a second time, so treat it as unconfirmed.
- Fix: redraw the field on every key from the first one, and show the placeholder only while the field is empty. Cap the echo at width minus 8 and show a count (`*** (41)`), so a long paste never reaches column 119.

### F04 Med: Ctrl-C message is mispositioned and sticky
- Screens: shots/30, shots/31 (row 8 at 120x36), shots/36. Size 120x36.
- Ctrl-C with text in the box prints `Use 'quit' or 'exit' to close.` in yellow at column 0 (all other text is indented 2), at row 8 under the header, far from the box. It pushes the page up one row so the top logo row is cut off (rows 0-3 become the logo's lower rows). The message stays on screen for the whole session and reappears again after later commands (rows 7, 14, 20 in different dumps). The first Ctrl-C on an empty box showed nothing.
- Fix: print the hint inside the prompt area (placeholder or a one-line notice above the status line) and clear it on the next key; never scroll the header.

### F05 Med: the subscription route tells the model a different workspace
- Screen: shots/38-progress-queued. Size 120x36.
- Two stray tasks (`C:/Program Files/Git/config`, from a shell path-conversion accident in this test) were refused with: "That path is outside the workspace folder, which is C:\Users\ALiam\AppData\Local\Temp\claude-cli-workdir." The real workspace was `C:\Coding\TMT\output\sim\ws` (shown in the header and /config). The first task still wrote into the right folder.
- Fix: pass the true workspace in the prompt for the subscription route and make sure the spawned `claude` process's working directory matches, so the model quotes the right path.

### F06 Med: duplicated final answer
- Screen: shots/34-run-done. Size 120x36.
- Row 16 `. I have created notes.txt in the workspace containing the word "hello".` and the box at rows 17-20 repeat each other; the boxed text ("The task is complete ... There is no further action needed.") adds nothing. The box border is dim, uses `┌─┐` edge to edge (cols 0-119), so it has no left margin; the refusal box in shots/38 uses a different corner style (`『 』`).
- The user's actual question was "tell me what you did"; the answer says nothing about the path or size.
- Fix: show the narration line only when it differs from the final text; indent the box by 2 and use one box style. Add tool detail to the row `Created file: notes.txt (path, 1 line)`.

### F07 Med: prompt box stranded at the top after the palette closes
- Screens: shots/42-slash-60x20, shots/43-task-60x20. Size 60x20 (also 80x24 was fine until the palette opened).
- With `/` typed the palette fills rows 4-17. Backspace closes it, but the box stays at rows 1-4 and rows 5-19 are blank (dump of shots/43: rows 1-4 only, then nothing). Typing more text keeps it at the top (shots/44). The history that was above is gone from view.
- Fix: after the palette closes, re-anchor the prompt to the bottom of the screen and repaint the transcript.

### F08 Med: Resume loses the visible conversation
- Screens: shots/48 (menu says "Resume  Go back to the session, which is still here"), shots/51-task-160x50. Size 160x50 (same at 120x36 and 80x24 behaviour not separately captured).
- After Resume the screen shows the logo, date, path and a new random tip (rows 1-8) and an empty area; the three earlier exchanges are not redrawn although /context says 3 turns are carried.
- Fix: repaint the transcript on Resume, or reword the menu line to say history is kept but not shown.

### F09 Med: status wording that is wrong or contradicts itself
- shots/06 (row 5): `API key  pay per use, with a key  (active)` while provider is OpenRouter. The `(active)` mark means "default route for Anthropic", not the active provider.
- shots/22 and shots/24: with route = Claude subscription and no Anthropic key stored, Settings row 4 says `API Key    key set` and the key screen says `Current   key set`, while `/config` (shots/37-slash-config row 29) says `API key       not set`.
- shots/25: main menu says `Provider  Anthropic` with no route; `/config` says `Provider      anthropic` in lower case.
- Fix: say `Claude subscription (no key needed)` in Settings and the menu; use one casing; show `(active)` only on the route used by the active provider.

### F10 Med: Settings rows clip at 80 and 60 columns
- shots/47-settings-80x24: row 13 `Keep TMT_Context/notes.md and progress.md in eac  OFF` is cut mid-word. shots/46-settings-60x20: rows 9, 12, 13, 14 are cut (`The credential that service is gi`, `Check for a newer TMT after   OFF`), and OFF/TAGS jump to the right edge (col 55-59) whereas at 120 cols they follow the text inline at varying columns (rows 12-14 in shots/04).
- Elsewhere an ellipsis is used (`...containing the wor…` in /context). Fix: truncate with `…`, and put the value in its own fixed column at every width.

### F11 Med: slash palette at 60x20
- shots/42: rows 6, 9, 10, 13, 14, 16, 17 cut mid-word (`forget the conversation, keep everything e`). The 14 entries plus box use 16 of 20 rows. Fix: ellipsis, and show at most (rows - 6) entries with scroll or filter-as-you-type.

### F12 Med: wrapped input
- shots/28-prompt-long (120x36): row 32 starts `   it please review` (three spaces, one too many; other continuation rows have two). shots/44 (60x20): `...what is sl` / `  ow please review...` splits a word, and rows 5 and 6 begin with 3 spaces.
- Fix: soft-wrap at word boundaries, keep the continuation indent at 2, and do not carry the trailing space to the next row.

### F13 Med: legacy welcome screen looks like another product
- shots/16 (rows 1-19): a 6-row box-drawing logo with a second strip of symbols (row 7), a double-line box 66 wide (rows 9-16), a progress bar that moves 40% to 55% on an empty entry, the old prompt `paste key`. Text says "It is saved to .tmt_key beside the code", but the new key screen says it is obfuscated and shows the key under Settings.
- A 1-character key (`h`) was left in `.tmt_key` after the review (removed during cleanup), which the new screen would have refused as too short. The cause was not isolated.
- Fix: retire this flow (see F02).

### F14 Low: contrast
- shots/03-help, shots/04-settings, shots/27: help body, descriptions, hints, the status line and the model narration are dim grey on near-black; the footers `Up/Down Navigate ...` and "Describe your first task" are barely readable on a laptop panel. The dim `+1 -0` and "Creating a file ..." lines in shots/34 are the same.
- Fix: lift the grey to about #8a8a8a (4.5:1 against #0c0c0c) and keep full white only for selection and content.

### F15 Low: selected-row colour changes per screen
- shots/04 selected row orange, shots/06 red (`> API key`), shots/07 and shots/16 title word in red. Red on near-black is the weakest contrast of the gradient. Fix: one selection colour; use the gradient only on logo and rules.

### F16 Low: inconsistent exit and help commands
- `Use 'quit' or 'exit' to close.` but `/` palette (shots/36) has no `/quit`, `/exit` or `/help`; Esc on the menu quits; Help lists only `/back`. Key hints vary: footers say `Esc Back` on sub-screens, nothing on the task prompt except the placeholder. Fix: list all keys and commands in the Help screen; add `/help` and `/quit`.

### F17 Low: wording and grammar
- `too short for a OpenRouter key` (shots/14, row 10): use "an".
- `+1 lines, -0 lines` (every status line): `+1 line`.
- `search is off until one has one` (shots/19, rows 3-4): "search stays off until a key is set".
- Tip `/effort high lets one task take up to 60 steps instead of 35` shows while `/config` already says `Effort high (... 60 rounds per task)`.
- `(no key yet)` on the menu vs `no key stored` in Settings.
- The Model screen is titled `Settings` (shots/18), the other sub-screens carry their own name.
- The Model Reply Format item has no description of what TAGS vs JSON means for the user; toggling only changes the label (shots/04 vs shots/20-replyformat-json) with no confirmation line.
- Help (shots/03) uses `--` for a dash and talks only about OpenRouter's free models.

### F18 Low: THINKING indicator
- shots/33: `THINKING` at row 34, col 0, below the closing rule, cycling among `THINKING`, bracket forms and non-BMP bold letters; bold math letters can render double width in some fonts. Fix: indent 2 and keep one ASCII style.

### F19 Low: queued tasks

(5s, 54 tokens)`), a third style besides the `THINKING` word and the status line. Fix: stamp the run start time and use one progress style.

### F20 Low: wide terminals

### F21 Low: alignment
- Header block (shots/02 rows 8-10): the label column is 10 wide, so `Workspace C:\Coding\TMT` and `Web Search not set` (Settings row 6) have a single space; others have two or more.
- Task screen (shots/27): the logo starts at col 0, the date, path and tip at col 2, and the prompt `>` at col 0 with text at col 2.

### F22 Low: Danger Zone paragraph width
- shots/21 rows 3-4: `...tmtcode command; anything git ignores stays, which` then `is your notes and TMT's saved key.` wraps at 118 columns, but the rest of the app wraps near 55. At 80 columns the same text would wrap oddly. Fix: use the same wrap width as other paragraphs.

## What works well
- Clear, consistent menu pattern: `>` marker, label plus description, footer with keys. Esc and Enter behave the same on every Settings sub-screen (Esc to the parent, Back item last, default cursor on Back in Danger Zone).
- The Anthropic route screen is clear, detects the installed Claude Code version (`Found Claude Code 2.1.310 and a Claude sign-in.`), and choosing "Claude subscription" saves in one step.
- The real task worked end to end on haiku through the subscription route: the live screen showed a status line, a `Created file: notes.txt` tool row with `+1 -0`, the meter line (`+1 lines, -0 lines, ~12k context, 5k out`) and the file contents were correct. There were no leftover rows after it finished.
- Multi-line paste is folded to `[Pasted text #1 +3 lines]`; Up recalls the earlier task with the hint `From history - Enter sends it as a new task`; Esc clears the line; queued tasks work (`1 queued task - Up to edit`).
- The slash palette (14 commands with one-line descriptions) and `/config`, `/context`, `/agents` are readable and well aligned.
- Start without a key goes straight to the key screen with a clear sentence; short-key validation message is helpful.
- Resizing live works: the main menu and the status line re-lay out cleanly at 80x24 and 60x20 (right clock drops at narrow width), and the main menu fits 60x20.
- The splash and menu logo have good colour and the rule gradient is attractive.

## Improvement ideas
1. One key-entry screen only; make Esc consistent everywhere and put `Esc` in the main menu footer (or disable it).
2. Add a hint row under the prompt: `Enter send  /  commands  Ctrl-C stop  Esc clear`.
3. Add `/help`, `/quit`, `/exit` to the palette and make Ctrl-C twice exit with a visible countdown line inside the box.
4. Show the route in the header: `Provider  Anthropic (Claude subscription)`, and show the subscription's remaining limit or last-use when available.
5. Add a width cap (about 100), `…` truncation and a scrolling palette for small windows; test at 60x20 in CI with a pyte snapshot.
6. Make the final answer one block: a header `Done`, then the answer, then a compact summary of tool rows (files created, commands run, elapsed time).
7. Give Reply Format two-line help (what TAGS and JSON change, and when to switch) and a confirmation line when toggled.
8. Raise the dim grey and give the selected row one colour; keep the gradient for decoration.
9. Keep a status line while the model thinks (`Thinking 12s`) at a fixed place instead of animated glyph sets.
10. Add a small automated TUI test using this driver: a fixed set of screens at 4 sizes with assertions for no line wider than the terminal, no mid-word clip, and no stale text after Esc.
